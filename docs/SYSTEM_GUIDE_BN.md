# ESP32 Network Shield — মাস্টার সিস্টেম ও আর্কিটেকচার গাইড (বাংলা)

এই বিস্তারিত গাইডে **ESP32 Network Shield**-এর সম্পূর্ণ কাজের মূলনীতি, ইন্টারনাল আর্কিটেকচার, সিস্টেম তৈরির পদ্ধতি (ফার্মওয়্যার বিল্ড ও ফ্ল্যাশিং) এবং ব্যবহারের নিয়মাবলি বিস্তারিতভাবে তুলে ধরা হয়েছে।

## ১. সিস্টেম পরিচিতি ও কাজের মূলনীতি

প্রতিটি ওয়েবসাইট ব্রাউজ করার সময় বা মোবাইল অ্যাপ চালানোর সময় শত শত গোপন ট্র্যাকার এবং বিজ্ঞাপনের রিকোয়েস্ট ব্যাকগ্রাউন্ডে তৈরি হয়। ব্রাউজার এক্সটেনশন কেবল ব্রাউজারের অ্যাড ব্লক করতে পারে, কিন্তু মোবাইলের অ্যাপ, ইউটিউব ক্লায়েন্ট কিংবা স্মার্ট টিভির বিজ্ঞাপন আটকাতে পারে না।

**ESP32 Network Shield** কাজ করে নেটওয়ার্ক লেয়ার ৩/৪ ও লেয়ার ৭ (DNS) পর্যায়ে:
1. **নেটওয়ার্ক ভূমিকা**: এটি বাসার লোকাল নেটওয়ার্কে একটি **Primary DNS Server** হিসেবে UDP পোর্ট ৫৩-তে দায়িত্ব নেয়।
2. **ফিল্টারিং লজিক**: যখন কোনো ডিভাইস ইন্টারনেটে যাওয়ার জন্য কোনো ডোমেইনের আইপি জানতে চায়:
   - **সাধারণ ওয়েবসাইট (Google, Facebook)**: ডিভাইসটি আসল আইপি ফিরিয়ে দেয় এবং দ্রুত অ্যাক্সেসের জন্য লোকাল ক্যাশে সেভ করে।
   - **বিজ্ঞাপন ও ট্র্যাকার (DoubleClick, Analytics)**: ফিল্টার ইঞ্জিন তৎক্ষণাৎ এটিকে সিঙ্কহোল (Sinkhole) করে `0.0.0.0` (IPv4) অথবা `::` (IPv6) উত্তর দেয়। ফলে ডিভাইসে বিজ্ঞাপন লোড হওয়াই বন্ধ হয়ে যায়।
3. **এনক্রিপশন অক্ষুণ্ণ রাখা**: এটি কোনো TLS/HTTPS ইন্টারসেপশন বা ম্যান-ইন-দ্য-মিডল প্রক্সি করে না। ফলে ব্যবহারকারীর গোপনীয়তা শতভাগ সুরক্ষিত থাকে এবং ব্রাউজিং স্পিড অত্যন্ত দ্রুত থাকে।

```
+---------------+     DNS রিকোয়েস্ট (:53)   +----------------------+      আসল DNS রিকোয়েস্ট (:53)   +------------------+
| ক্লায়েন্ট     | -----------------------> | ESP32 Network Shield | -----------------------------> | আপস্ট্রিম DNS     |
| (ফোন/ল্যাপটপ) | <----------------------- | (ব্লুম ফিল্টার + রুল) | <----------------------------- | (Cloudflare 1.1) |
+---------------+     বিজ্ঞাপন: 0.0.0.0     +----------------------+      সাধারণ সাইট: আসল IP       +------------------+
```

## ২. সিস্টেম আর্কিটেকচার ও ডেটা ফ্লো

### DNS পাইপলাইন ও ফিল্টারিং ক্রমানুসার (Rule Hierarchy)

পোর্ট ৫৩-তে আসা প্রতিটি UDP ডেটাগ্রাম একটি নির্ধারিত পাইপলাইন দিয়ে ধাপে ধাপে যাচাই করা হয়:

```
ইনকামিং UDP ডেটাগ্রাম (পোর্ট ৫৩)
   │
   ▼
[১] parse_dns_query() ──────────► ক্ষতিকর বা অবৈধ প্যাকেট হলে সাথে সাথে বাতিল
   │
   ▼
[২] normalize_domain() ─────────► ছোট হাতের অক্ষরে রূপান্তর ও ট্রেইলিং ডট অপসারণ
   │
   ▼
[৩] DnsCache::lookup() ─────────► ক্যাশে পাওয়া গেলে সাথে সাথে রেসপন্স প্রেরণ (০ ms লেটেন্সি)
   │ (ক্যাশে না পেলে)
   ▼
[৪] RuleEngine::decide()
   ├── Allowlist চেক ───────────► ডোমেইন অনুমোদিত হলে ──► ALLOW
   ├── Custom Rules চেক ────────► ব্যবহারকারীর নিজস্ব রুল ──► রুল অনুযায়ী ফলাফল
   └── Blocklist চেক ───────────► ব্লুম ফিল্টার (Bloom Filter):
                                    ├── নেগেটিভ (লিস্টে নেই) ──► ALLOW
                                    └── পজিটিভ (ম্যাচ পাওয়া গেছে) ──► ফ্ল্যাশে বাইনারি সার্চ
                                                                      ├── নিশ্চিত ব্লক ──► BLOCK
                                                                      └── ভুল সংকেত ──► ALLOW
   │
   ├── যদি BLOCK হয়: 0.0.0.0 / :: রেসপন্স পাঠিয়ে দেওয়া হয়।
   └── যদি ALLOW হয়: আপস্ট্রিমে পাঠিয়ে আসল আইপি আনা হয় এবং ক্যাশে রাখা হয়।
```

### মেমরি বাজেট ও ব্লুম ফিল্টার + ফ্ল্যাশ বাইনারি সার্চ

ক্লাসিক ESP32-এর মোট মেমরি মাত্র ~৩২০ KB DRAM, যেখানে ৫০,০০০ ডোমেইনের টেক্সট মেমরিতে রাখা অসম্ভব। তাই Shield একটি দুই-ধাপের আর্কিটেকচার ব্যবহার করে:
1. **RAM ব্লুম ফিল্টার**: মেমরিতে মাত্র ~৬০ KB-এর একটি বিট-অ্যারে থাকে যা ৩টি FNV-1a হ্যাশ ফাংশন দিয়ে পরিচালিত। লিস্টে না থাকা ডোমেইনগুলোকে এটি $O(1)$ সময়ে মেমরি থেকেই বাদ দিয়ে দেয়।
2. **Flash বাইনারি সার্চ (`BlocklistFile`)**: যদি ব্লুম ফিল্টারে কোনো ম্যাচ আসে, তখন সিস্টেম LittleFS ফ্ল্যাশ ড্রাইভ থেকে সাজানো ফাইলটিতে বাইনারি সার্চ ($O(\log N)$) করে নিশ্চিত হয়।

### অপারেটিং মোড: DNS মোড বনাম ট্রাভেল মোড (হার্ডওয়্যার NAPT)

ফার্মওয়্যারটিতে দুটি অপারেটিং মোড রয়েছে:

#### ১. DNS Mode (`mode = "dns"`)
- ESP32 বাসার মূল ওয়াই-ফাইতে ক্লায়েন্ট হিসেবে যুক্ত থাকে (`WIFI_MODE_STA`)।
- বাসার মূল রাউটারের DHCP DNS-এ ESP32-এর আইপি (`192.168.0.156`) বসানো হয়।
- যেকোনো ডিভাইস থেকে `http://192.168.0.156` অথবা `http://esp32-shield.local` দিয়ে ড্যাশবোর্ড দেখা যায়।

#### ২. Travel Mode (`mode = "travel"`)
- ESP32 একই সাথে Wi-Fi ক্লায়েন্ট এবং অ্যাক্সেস পয়েন্ট হিসেবে চলে (`WIFI_MODE_APSTA`)।
- **STA ইন্টারফেস**: ইন্টারনেট পাওয়ার জন্য বাসার বা হোটেলের মূল ওয়াই-ফাইতে যুক্ত থাকে।
- **SoftAP ইন্টারফেস**: নিজেই একটি নিরাপদ ওয়াই-ফাই নেটওয়ার্ক ছড়ায় (যেমন: `Shield-AdBlock`, আইপি `192.168.4.1`)।
- **হার্ডওয়্যার NAPT**: এতে lwIP IPv4 NAPT (`CONFIG_LWIP_IP_FORWARD=y` এবং `CONFIG_LWIP_IPV4_NAPT=y`) সক্রিয় থাকে। যারা এই ওয়াই-ফাইতে যুক্ত হবে, তাদের সমস্ত ইন্টারনেট ট্রাফিক সরাসরি ESP32-এর মাধ্যমে রাউট হয়। কোনো রাউটার পরিবর্তন বা ডিভাইসে সেটিং ছাড়াই স্বয়ংক্রিয়ভাবে ১০০% অ্যাড ব্লকিং চালু হয়ে যায়।

### ওয়েব ড্যাশবোর্ড ও REST / WebSocket ইঞ্জিন

- **এমবেডেড সিঙ্গেল-পেজ অ্যাপ**: `main/web_dashboard/index.html` ফাইলটি সরাসরি ফার্মওয়্যারের মধ্যে কম্পাইল করা থাকে।
- **নিরাপদ REST API**:
  - `GET /api/status`: ডিভাইসের লাইভ অবস্থা (পাবলিক)।
  - `GET /api/config` ও `PUT /api/config`: কনফিগারেশন পরিবর্তন (Bearer Token সুরক্ষিত)।
  - `GET /api/stats`: মোট রিকোয়েস্ট, ব্লকড রিকোয়েস্ট ও পার্সেন্টেজ।
  - `GET /api/devices`: কানেক্টেড ডিভাইসের আইপি ও ম্যাক অ্যাড্রেস।
  - `POST /api/reboot`: সফটওয়্যার রিবুট।
- **লাইভ WebSocket (`/ws`)**: ব্রাউজারে সেকেন্ডে সেকেন্ডে লাইভ ট্রাফিক ও রিকোয়েস্ট চার্ট আপডেট করে।

## ৩. সিস্টেম তৈরির পদ্ধতি (How I Make the System)

### হার্ডওয়্যার স্পেসিফিকেশন

- **মাইক্রোকন্ট্রোলার**: ESP32-D0WD-V3 (Dual Core Xtensa @ 240 MHz, 520 KB SRAM)।
- **ফ্ল্যাশ মেমরি**: 4 MB SPI Flash (DIO মোড @ 40 MHz)।
- **ইউএসবি ব্রিজ**: CP2102 বা CH340 চিপসেট।

### পার্টিশন টেবিল বিন্যাস (`partitions.csv`)

৪ মেগাবাইট ফ্ল্যাশ মেমরিকে নিখুঁতভাবে ভাগ করা হয়েছে:

```csv
# Name,   Type, SubType, Offset,   Size,     Flags
nvs,      data, nvs,     0x9000,   0x6000,
phy_init, data, phy,     0xf000,   0x1000,
factory,  app,  factory, 0x10000,  0x140000,
ota_0,    app,  ota_0,   0x150000, 0x140000,
otadata,  data, ota,     0x290000, 0x2000,
littlefs, data, 0x83,    0x292000, 0x16e000,
```

- `factory` (১.২৮ MB): মূল ফার্মওয়্যার বাইনারি থাকে।
- `ota_0` (১.২৮ MB): ওভার-দ্য-এয়ার দূরবর্তী আপডেটের জন্য সংরক্ষিত।
- `littlefs` (১.৪৪ MB): ব্লকলিস্ট ফাইল, অ্যালাউলিস্ট এবং লাইভ স্ট্যাটাস ধারণ করে।

### NVS স্টোরেজ ও প্রি-প্রভিশনিং

ESP-IDF NVS-এ সর্বোচ্চ কি-এর দৈর্ঘ্য **১৫ অক্ষর**। তাই ফার্মওয়্যারে বড় নামগুলোকে এভাবে ম্যাপ করা হয়েছে:

| প্যারামিটার | NVS Key (<= ১৫ অক্ষর) | বিবরণ |
|---|---|---|
| `wifi_ssid` | `wifi_ssid` | মূল Wi-Fi-এর নাম |
| `wifi_pass` | `wifi_pass` | মূল Wi-Fi-এর পাসওয়ার্ড |
| `api_token` | `api_token` | ৩২ অক্ষরের সিক্রেট হেক্স টোকেন |
| `mode` | `mode` | অপারেটিং মোড (`dns` বা `travel`) |
| `ap_ssid` | `ap_ssid` | ট্রাভেল হটস্পটের নাম (`Shield-AdBlock`) |
| `ap_pass` | `ap_pass` | ট্রাভেল হটস্পটের পাসওয়ার্ড (`shield1234`) |
| `upstream_primary` | `up_primary` | প্রধান DNS (`1.1.1.1`) |
| `upstream_secondary` | `up_secondary` | সেকেন্ডারি DNS (`1.0.0.1`) |

### স্বয়ংক্রিয় GitHub Actions CI/CD পাইপলাইন

উইন্ডোজে জটিল টুলচেইনের ঝামেলা এড়াতে আমাদের রিপোজিটরিতে [`.github/workflows/build.yml`](../.github/workflows/build.yml) তৈরি করা হয়েছে। 

```yaml
name: Build Firmware
on:
  push:
    branches: [ main ]
```

যখনই গিটহাবে কোড পুশ করা হয়:
1. GitHub Actions রানার স্বয়ংক্রিয়ভাবে অফিসিয়াল `espressif/idf:v5.1.4` ডকার কনটেইনার চালু করে।
2. ফার্মওয়্যার কম্পাইল করে এবং ৩টি বাইনারি (`bootloader.bin`, `partition-table.bin`, `esp32-network-shield.bin`) তৈরি করে।
3. GitHub Release `v0.5.0`-এ স্বয়ংক্রিয়ভাবে আপলোড করে দেয়।

### `esptool.py` দিয়ে ফ্ল্যাশিং পদ্ধতি

কম্পাইল করা বাইনারিগুলো বোর্ডের সঠিক অফসেটে ফ্ল্যাশ করা হয়:

```bash
# ১. বুটলোডার (০x১০০০)
python -m esptool --chip esp32 -p COM7 -b 460800 write_flash 0x1000 bootloader.bin

# ২. পার্টিশন টেবিল (০x৮০০০)
python -m esptool --chip esp32 -p COM7 -b 460800 write_flash 0x8000 partition-table.bin

# ৩. এনভিএস কনফিগারেশন (০x৯০০০)
python -m esptool --chip esp32 -p COM7 -b 460800 write_flash 0x9000 nvs.bin

# ৪. মূল ফার্মওয়্যার (০x১০০০০)
python -m esptool --chip esp32 -p COM7 -b 460800 write_flash 0x10000 esp32-network-shield.bin
```
